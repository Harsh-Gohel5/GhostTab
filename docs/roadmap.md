# MVP roadmap

The target is one complete, convincing developer workflow within the hackathon
window. The wider multi-service, zero-click product remains a longer-term goal.

| Milestone | Completion criteria | Status |
| --- | --- | --- |
| Foundation | Public repo, runnable interface/API, documented setup, passing local checks and CI configuration | Initial implementation |
| Live GitHub | A selected issue yields authorized, commit-pinned source evidence; webhook verification and replay handling work | Planned |
| Meta reasoning | Real model calls produce a brief with validated citations, candidate files and explicit unknowns | Planned |
| Workspace assembly | Inspect evidence and open an isolated checkout through an authenticated local bridge | Planned |
| Freshness | A relevant issue or commit update marks context stale and produces a replacement without duplicates | Planned |
| Second source | One chosen messaging service adds useful discussion evidence with authorization enforced | Planned |
| Demo and submission | Reproducible setup, measured end-to-end example, public repo and three-minute video | Planned |

## First demonstration candidate

Use an authorized synthetic repository containing a pagination bug and supporting
issue/documentation. Prepare its context, show unresolved contract questions, then
introduce a relevant commit and demonstrate stale detection and refresh. This is
a candidate story, not evidence of implemented functionality.

## Decisions before connected implementation

- Confirm team size and available build time.
- Verify Meta API access and eligible model selection.
- Choose the first repository and the messaging service.
- Confirm the local editor target; Windows is the current development platform.
- Choose persistent storage and job delivery for the first live workflow.

## Event constraints supplied by the owner

The supplied kickoff screenshots state a build window of October 26–November 4,
2026, a public repository, teams of up to four, and submission by November 4 at
9:00 PM ET. They require an event-platform submission and three-minute demo.
These notes transcribe supplied context; verify final submission instructions
with the organizer before submitting.

Prioritize measurable user benefit, substantive use of Meta AI, engineering
correctness, and a demo that works end to end. Leave time for recording and
submission rather than scheduling feature work up to the deadline.
